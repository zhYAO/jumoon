# JUMOON 前端性能基线与验收

适用于登录、工作台、看板、业务列表和系统管理。下面的基线来自当前前端。预算用于后续开发和 CI 验收，后端接入后还需用真实认证和接口复测。

## 优化前生产构建

2026-11-24 在提交 `44cadb63925e` 上用 Windows、Node 22.15.0、pnpm 10.33.2 执行 `pnpm build`，已有依赖，单次耗时 **53.0 秒**。全站共有 37 个 JS、11 个 CSS 文件，逐文件 gzip level 6 后合计 **1,394,900 B**。下表按 `dist/index.html` 与 Umi 生成的 `dist/preload_helper.js` 解析直达各路由的资源，按 URL 去重后分别求和。单位均为字节，不含图片、HTML 和 API 响应。

| --- | ---: | ---: |
| 商务工作台 `/home` | 1,029,748 | 2,413 |
| 看板 `/analytics` | 1,029,472 | 2,187 |

优化前，工作台与看板在路由就绪前都等待完整 ECharts 依赖块。该块占 **394,716 B gzip-6**，约为工作台冷启动 JS 的 **38%**。公共入口 `umi.js` 另占 **424,512 B gzip-6**。这两个大小分别包含在表内，其他路由的异步包不应计入工作台。[前端构建配置](../config/config.ts)

浏览器为 Chromium 151.0.7922.34，1365 × 768、DPR 1，每次使用全新浏览器上下文直达 `/home`。本地 HTTP/1.1 服务使用 gzip level 1，权限接口使用本地固定响应，沿用仓库业务种子数据并阻止外网请求。每次都呈现 3 行项目、2 张非空图表，实际收到 13 个 JS 响应，共 **1,150,932 B gzip-1**。限速组 LCP 范围为 4.732–7.536 s；用同机、同协议和同压缩级别复测。ECS、真实接口延迟和线上用户分位值尚待采集。

## 图表拆包复测

在原生产包和基于同一提交的工作区生产包之间交错执行，每条路由每版冷启动 5 次。使用商务角色、相同业务种子数据、本地权限响应和上面的 Chromium 限速档。这次成对复测的新基线用于计算改善幅度。

| 路由 | 首屏 JS，gzip-6 | LCP 中位数 | 四项 KPI 可见中位数 | 首张图可交互中位数 |
| --- | ---: | ---: | ---: | ---: |
| 工作台 `/home` | 1,029,748 → 637,813 B | 4.052 → 3.156 s | 3.650 → 3.146 s | 4.636 → 4.804 s |
| 看板 `/analytics` | 1,029,472 → 637,467 B | 4.284 → 3.104 s | 3.828 → 3.092 s | 5.229 → 4.849 s |

图表可交互时间在同条件的独立复测中采样。从导航开始计时，画布首次绘制后移动鼠标，记录首次出现真实数据提示框的时间。工作台首张图的交互中位数增加 0.168 s，同时首屏 LCP 改善 22.1%。

独立的图表依赖块从 394,716 B 降至 235,401 B（gzip-6）。两条路由的全部 JS 在首张图绘制前已收到。按浏览器 gzip-1 响应体计，工作台从 1,150,932 B 降至 972,849 B，看板从 1,150,590 B 降至 972,459 B。[图表加载](../src/domains/product/charts/DemoChart.tsx) · [图表渲染器](../src/domains/product/charts/ChartRenderer.tsx)

将图表包响应延后 3 秒，商务工作台的「新建 Campaign」与财务看板的「去财务审批」仍可在图表出现前打开目标页。另在限速档每版测 5 次，按钮一可点击即操作。工作台从导航开始到项目页标题可见的中位数由 6.310 s 降至 5.178 s，其中点击到标题可见由 1.318 s 变为 1.371 s。

另验证图表包请求失败、屏外图表滚动后加载、提示框和图例切换，以及商务、财务、经营三个角色的指标与表格和基线一致。登录页未请求图表依赖。

## 首轮开发顺序

1. **先让首页指标和操作可用。** 把轻量的图表配置与渲染器分开，在图表组件中异步加载 `echarts/core`，只注册页面使用的柱状图、折线图、饼图、坐标系、图例、提示框和渲染器。保持图表高度，首屏图随页面挂载发起加载，屏外图按需加载。用慢速或延迟的图表响应验证首页标题、金额和操作先出现；再验证图表显示、图例和提示框。[Apache ECharts 按需导入](https://echarts.apache.org/handbook/en/basics/import/)
2. **按页面实际用途缩小公共资源。** 对照构建模块明细检查全局布局、日期库与语言包。列表专用组件留在列表路由，登录、改密和首页分别核对实际下载。侧栏 28 px 标识和表单 48 px 标识目前复用 81,215 B 的大图；为小标识提供适配像素密度的资源，保留登录品牌大图的清晰度，实测新资源的合计传输量。[应用布局](../src/app.tsx) · [登录页](../src/pages/Login/index.tsx)
3. **减少随业务数据增长的计算。** 只计算当前角色展示的图表，用项目 ID 与月份建立索引，按授权口径聚合。对照相同样本核对金额、排序、空月份、空状态和可见范围。特别覆盖可见项目的整体合作成本、仅扣已付金额的未结清额，以及按付款更新时间或项目结算月统计的两种趋势。真实后端接入后由服务端分页和汇总。[工作台](../src/pages/Home/index.tsx) · [角色看板](../src/pages/Analytics/index.tsx) · [后端技术基线](backend-architecture.md)
4. **使重复访问与跨版本切换都可用。** 当前 `umi.js`、异步块和预加载脚本使用固定名称。让每版 HTML 引用匹配的运行时、预加载映射和静态资源，可使用内容指纹，或为生成器保留的固定文件名添加版本目录。仅对 URL 随内容变化的资源设置长缓存和 `immutable`。HTML 与可变的固定 URL 每次重新验证，认证响应继续使用 `no-store`。验证 gzip 协商、`Vary: Accept-Encoding`、缓存命中与失效；缺失的 JS、CSS、图片返回 404。若需生产错误定位，source map 按版本保存到受限诊断产物中。发布及回滚窗口内保持旧 HTML 引用的静态资源可达。[HTTP 缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Caching) · [发布验收](ci-cd-release.md)

## 预算与放行

| 验收对象 | 首轮目标与判断方法 |
| --- | --- |
| 首屏 JS | 首轮图表优化要求工作台与看板的**路由就绪所需 JS 各 ≤ 800 KiB gzip-6**，并证明人为延迟图表请求时 KPI、列表和主要入口仍可用。分别报告首屏依赖、首张图可交互前下载的全部 JS、全页总量。在登录页检查图表请求数为 0。 |
| 浏览器体验 | 固定上面的限速档，对基线和候选交错各测至少 5 次。首轮首页 LCP 中位数改善目标为 ≥ 20%。从导航开始另测实际 KPI 可见、第一张图可交互、点击主操作到目标内容出现。对照相同夹具，其余关键动作若中位数同时变慢超过 10% 和 100 ms，再各测 5 次；持续退化时修正或在 PR 说明功能代价并由维护者决定。 |
| 上线体验 | 在能获得足量真实访问样本时，按桌面和移动端分别观察 p75，目标为 LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1。记录窗口、样本量及版本。SPA 站内切换单独测“点击到目标数据可用”，低流量期间保留实验室结果和样本数。[Core Web Vitals 指标及阈值](https://web.dev/articles/vitals) |
| 正确性与回归 | 商务、财务、经营角色分别核对首页指标和图表；登录/恢复、看板切换、项目列表筛选与分页、系统用户列表各走一次真实操作。覆盖冷启动、暖缓存回访、深链接及旧标签页跨发布导航。真实后端就绪后，候选镜像的联调使用临时账号和真实数据库。 |

**复测方法。** 用同一锁文件、Node/pnpm、浏览器版本、视口、夹具与服务器配置对比基线提交和候选提交。静态预算将每个原始响应文件用 gzip level 6 独立压缩，同一路由共享的 URL 只计一次。构建器的路由清单用于识别阻塞依赖，浏览器网络记录用于发现动态请求、预加载和缓存复用。发布记录附原始样本、中位数、路由字节差和关键请求瀑布图；保留上次通过的预算，在实测改善后收紧。影响公共入口时跑全表，只改单页时重点测该页与共享入口。[CI 执行规则](ci-cd-release.md)
