## 1. 子系统概述

### 1.1 定位

系统管理是 JUMOON 业务管理系统的**基础子系统**，负责公司内部人员如何进入系统、以何种身份使用系统、以及组织与权限如何配置。

本子系统不承载达人、项目、建联等业务数据；业务模块上线后，统一挂在本子系统所建立的账号与权限体系之上。

### 1.2 解决什么问题

| 问题 | 本子系统提供的能力 |
|------|-------------------|
| 谁可以进系统 | 员工账号（工作邮箱 + 密码）、启用/停用 |
| 进了之后能做什么 | 角色绑定菜单与操作权限 |
| 组织怎么挂 | 部门树；用户归属部门 |
| 密码怎么管 | 仅管理员为员工重置密码（无员工自助找回） |
| 侧栏与按钮从哪来 | 菜单树（目录 / 页面 / 操作点）由系统管理维护 |

### 1.3 使用对象

| 对象 | 使用方式 |
|------|----------|
| 全体员工 | 登录、退出；使用被授权的业务与管理功能 |
| 系统管理员 / 超管 | 维护部门、角色、菜单、用户账号与密码重置 |
| 普通业务角色 | 默认不进入系统管理（除非被授予相应权限） |

### 1.4 登录与会话（产品规则）

- 登录方式：**工作邮箱 + 密码**（唯一方式）。  
- 账号状态为「停用」时不可登录。  
- **不提供**员工自助「忘记密码 / 邮箱验证码登录」。  
- 同一账号允许在多台设备同时保持登录；退出仅结束当前端会话。  
- 管理员重置密码后，该账号原有登录会话失效，须使用新密码重新登录。

## 2. 信息架构

系统管理在产品侧由以下模块组成：

```
登录
 └── 工作台（首页）
      └── 系统管理
           ├── 用户管理
           ├── 角色管理
           ├── 菜单管理
           └── 部门管理
```

侧栏「系统管理」下四个子模块是否可见，取决于当前用户被授予的权限；无权限则不展示对应入口。

## 3. 登录

### 3.1 功能说明

员工通过登录页进入系统。系统校验邮箱与密码，以及账号是否处于可用状态。

### 3.2 界面要素

| 要素 | 产品定义 |
|------|----------|
| 工作邮箱 | 登录标识；须为合法邮箱格式 |
| 密码 | 与账号绑定的凭证 |
| 登录 | 提交校验；成功进入系统首页；失败给出原因类提示（账号或密码错误 / 已停用 / 临时限制等） |

### 3.3 产品规则

1. 系统不开放自助注册；账号须由管理员在「用户管理」中创建。  
2. 连续登录失败达到系统设定次数后，可在一段时间内禁止再次尝试（防暴力破解）。  
3. 登录成功后，系统按该用户角色加载可访问菜单与可执行操作。

---

## 4. 全局框架（登录后）

### 4.1 功能说明

登录后统一工作台框架：品牌标识、导航菜单、当前用户信息与退出。

### 4.2 界面要素

| 要素 | 产品定义 |
|------|----------|
| Logo / 产品名 | 展示 JUMOON 品牌 |
| 侧栏菜单 | 仅展示当前用户有权访问的模块与页面 |
| 当前用户 | 展示昵称或邮箱 |
| 退出登录 | 结束当前会话并返回登录页 |

### 4.3 产品规则

1. 菜单可见性由角色权限决定，不因前端藏菜单而改变后端鉴权结果。  
2. 退出后需重新登录才能访问需鉴权页面。

## 5. 用户管理

### 5.1 功能说明

维护公司员工在系统中的账号：创建、查询、编辑、停用/删除，以及管理员重置密码。  
**邮箱即登录账号。**

### 5.2 列表能力

| 能力 | 产品定义 |
|------|----------|
| 列表展示 | 展示用户 ID、邮箱、昵称、状态、所属部门等 |
| 按邮箱筛选 | 按登录邮箱查询 |
| 按昵称筛选 | 按显示名查询 |
| 按状态筛选 | 正常 / 停用 |
| 查询 | 按条件刷新列表 |
| 重置（筛选） | 清空筛选条件 |
| 刷新 | 重新加载当前列表数据 |
| 密度 / 列设置 | 调整表格显示密度与可见列（不影响业务数据） |

### 5.3 功能点（按钮级）

| 功能点 | 产品定义 | 规则与结果 |
|--------|----------|------------|
| **新建用户** | 开通一名员工账号 | 须填写邮箱、初始密码、昵称等；邮箱全局唯一；创建后即可按状态登录 |
| **编辑** | 修改用户资料与授权 | 可改昵称、部门、角色、状态、备注等；**邮箱创建后不可修改** |
| **重置密码** | 管理员为指定用户设定新密码 | 新密码长度不少于 6 位；成功后该用户旧会话失效 |
| **删除** | 移除用户账号 | 须二次确认；删除后不可再登录（逻辑删除，便于审计与误删恢复策略由实现保证） |

### 5.4 新建 / 编辑用户 · 字段说明书

| 字段 | 新建 | 编辑 | 说明 |
|------|------|------|------|
| 邮箱 | 必填 | 只读 | 登录账号 |
| 初始密码 | 必填（≥6 位） | 无此字段 | 仅创建时设定；之后改密走「重置密码」 |
| 昵称 | 必填 | 可改 | 界面显示名 |
| 部门 | 选填 | 可改 | 归属组织节点；供数据范围使用 |
| 角色 | 选填（可多选） | 可改 | 决定菜单与操作权限；多角色时权限合并 |
| 状态 | 必填 | 可改 | **正常**：可登录；**停用**：不可登录 |
| 备注 | 选填 | 可改 | 内部说明 |

弹窗操作：

| 操作 | 产品定义 |
|------|----------|
| 确定 | 校验通过后保存 |
| 取消 | 关闭，不保存 |

### 5.5 业务规则

1. 禁止开放注册；所有账号由管理员创建。  
2. 停用优先于删除，用于离职、长假、违规停用等场景。  
3. 一人可绑定多个角色；实际权限为各角色权限的并集。  
4. 重置密码权限应严格控制（能重置密码 ≈ 可接管该账号）。

## 6. 角色管理

### 6.1 功能说明

角色是权限的打包单位：规定「这类岗位能看到哪些页面、能执行哪些操作、数据能看多大范围」，再赋给用户。

### 6.2 列表能力

| 能力 | 产品定义 |
|------|----------|
| 列表展示 | 角色 ID、名称、编码、排序、状态、数据范围 |
| 按名称 / 编码 / 状态筛选 | 查询角色 |
| 查询 / 重置 / 刷新 / 密度 / 列设置 | 同用户管理列表工具 |

### 6.3 功能点（按钮级）

| 功能点 | 产品定义 | 规则与结果 |
|--------|----------|------------|
| **新建角色** | 创建一种岗位权限模板 | 设定编码、数据范围，并勾选菜单与操作 |
| **编辑** | 调整角色配置 | 可改名称、排序、状态、数据范围、菜单勾选等；内置角色的编码不可改 |
| **删除** | 删除角色 | 须二次确认；删除前应确认无必要用户依赖 |

### 6.4 新建 / 编辑角色 · 字段说明书

| 字段 | 说明 |
|------|------|
| 角色名称 | 展示用，如「商务 BD」「财务」 |
| 角色编码 | 系统识别用，如 `bd`、`finance`；内置超管为 `super_admin` |
| 排序 | 列表展示顺序 |
| 状态 | **正常**：对用户生效；**停用**：持有该角色的用户不再获得其权限 |
| 数据范围 | 见 §6.5 |
| 自定义部门 | 仅当数据范围 =「指定部门」时出现；勾选可见部门 |
| 菜单权限 | 树形勾选：目录、页面、操作（按钮）；决定侧栏与页面按钮 |
| 备注 | 说明 |

弹窗操作：**确定**保存；**取消**关闭。

### 6.5 数据范围（产品定义）

| 选项 | 含义 |
|------|------|
| 全部数据 | 不按部门/本人限制行数据 |
| 指定部门 | 仅可见勾选的部门范围内数据 |
| 本部门 | 仅可见用户所属部门数据 |
| 本部门及以下 | 可见所属部门及其下级部门数据 |
| 仅本人 | 仅可见本人相关数据 |

说明：功能权限（能不能进、能不能点）由「菜单权限」控制；数据范围控制业务数据上线后「能看见哪些行」。当前先完成配置模型，业务列表启用过滤后按本定义执行。

用户拥有多个角色时，数据范围按**并集**理解（例如任一角色为「全部」，则视为全部）。

### 6.6 预置角色（产品种子）

| 角色名称 | 编码 | 说明 |
|----------|------|------|
| 超级管理员 | `super_admin` | 内置；具备全部功能权限与全部数据范围 |
| 管理员 | `manager` | 偏系统配置 |
| 项目经理 | `pm` | 业务协作向 |
| 商务 BD | `bd` | 默认偏本部门数据范围 |
| 运营 | `operator` | 默认偏本部门数据范围 |
| 财务 | `finance` | 财务相关配置向 |
| 实习生 | `intern` | 默认偏仅本人 |

实际菜单勾选可按公司制度调整；超管账号须严格控制数量。

## 7. 菜单管理

### 7.1 功能说明

菜单管理维护系统的**导航结构**与**操作权限点**。  
角色通过勾选菜单项获得能力；页面上的按钮是否出现、接口是否允许，均对应此处的权限标识。

本模块面向系统管理员 / 实施人员；日常业务同学一般不使用。

### 7.2 类型定义

| 类型 | 产品含义 |
|------|----------|
| 目录 | 侧栏分组节点，不对应独立业务页 |
| 菜单 | 对应一个可访问页面 |
| 按钮 | 对应一个操作权限点（不单独占侧栏项） |

### 7.3 列表能力

| 能力 | 产品定义 |
|------|----------|
| 树形列表 | 按上下级展示全部菜单与按钮 |
| 展示列 | 名称、类型、权限标识、路由、排序、状态 |
| 刷新 / 密度 / 列设置 | 显示辅助 |

### 7.4 功能点（按钮级）

| 功能点 | 产品定义 | 规则与结果 |
|--------|----------|------------|
| **新建** | 在根级创建目录 / 菜单 / 按钮 | 需指定类型与必要字段 |
| **新增子项** | 在当前节点下增加子级 | 用于挂子菜单或操作按钮 |
| **编辑** | 修改节点属性 | 可改名称、路由、权限标识、状态等 |
| **删除** | 删除节点 | 须二次确认；存在子节点时应先处理子节点 |

### 7.5 新建 / 编辑菜单 · 字段说明书

| 字段 | 适用 | 说明 |
|------|------|------|
| 上级菜单 | 全部 | 挂载位置；可为根 |
| 名称 | 全部 | 展示名称 |
| 类型 | 全部 | 目录 / 菜单 / 按钮 |
| 路由 | 目录、菜单 | 前端路径片段 |
| 组件 | 目录、菜单 | 前端页面组件路径 |
| 图标 | 目录、菜单 | 侧栏图标（可选） |
| 权限标识 | 按钮必填；菜单可选 | 如 `system:user:create`；角色勾选与鉴权的依据 |
| 排序 | 全部 | 同级展示顺序 |
| 状态 | 全部 | 正常 / 停用 |

弹窗操作：**确定** / **取消**。

### 7.6 系统管理模块已定义的操作权限点

以下权限点由产品预置，供角色勾选；与界面功能一一对应。

**用户管理**

**菜单管理**

| 权限标识 | 对应功能 |

| `system:menu:create` | 新建 / 新增子项 |

**部门管理**

## 8. 部门管理

### 8.1 功能说明

维护公司组织架构树。用户归属部门后，角色上的「本部门 / 本部门及以下 / 指定部门」等数据范围才有组织依据。

### 8.2 列表能力

| 能力 | 产品定义 |
|------|----------|
| 树形列表 | 展示部门层级 |
| 展示列 | 名称、排序、状态 |
| 刷新 / 密度 / 列设置 | 显示辅助 |

### 8.3 功能点（按钮级）

| 功能点 | 产品定义 | 规则与结果 |
|--------|----------|------------|
| **新建** | 在根下创建部门 | |
| **新增子部门** | 在当前部门下创建下级 | |
| **编辑** | 修改名称、上级、排序、状态 | |
| **删除** | 删除部门 | 须二次确认；删除前应先将下属人员调整到其他部门 |

### 8.4 新建 / 编辑部门 · 字段说明书

| 字段 | 说明 |

弹窗操作：**确定** / **取消**。

## 9. 跨模块产品规则

1. **权限以服务端校验为准**：界面隐藏按钮不等于可绕过；无权限调用接口须失败。  
2. **配置顺序建议**：部门 → 角色（勾菜单）→ 用户（选部门与角色）。  
3. **角色变更生效**：用户重新获取权限信息后生效（通常需重新登录）。  
4. **超管**：角色编码 `super_admin` 具备全部功能能力；数量须最少。  
5. **状态约定（产品语义）**：「正常」可用；「停用」不可用。  
6. **停用 / 删除 / 配置组合**：详见同目录《[系统管理-停用删除与配置组合说明](./系统管理-停用删除与配置组合说明.md)》。
